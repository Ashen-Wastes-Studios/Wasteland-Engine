# Neural rendering evidence

Every number in `docs/NEURAL_RENDERING.md` traces to a file here or to a command that
regenerates it. Nothing in this directory is decorative, and nothing here is a
screenshot of a menu.

## What is here

| file | what it is |
|---|---|
| `neural_stage_ab.png` | stage-off (left) vs stage-on (right), same camera, same frame |
| `neural_stage_verification.txt` | the measured comparisons behind the +2.935 dB and the shader-parity claim |
| `baseline_*.png` / `baseline_*.log` | Task 3 baseline captures, before the in-estimator change |
| `after_*.png` / `after_*.log` | Task 3 captures after it |
| `BACKUP_SHA256.txt` | hashes of the shaders as they were before Task 3's edits |

## About the PNG file size

Every capture here is exactly **10,153,485 bytes**. That is not a coincidence and it is
not a bug: the engine's hand-rolled writer in `DemonCore-Editor/src/EditorLayer.cpp`
emits **stored (uncompressed) deflate blocks**, so each file is the raw pixel payload
plus a fixed container overhead. File size therefore carries **no information** about
the image and must never be used as a signal — a blank frame and a full frame are the
same size.

## Reproducing the comparison

The float dumps are not kept here (54 MB each). They are regenerated by running the
editor with the capture hooks and comparing:

```
WASTELAND_PIN_CAMERA="0.0,0.0,0.0,13.3,-30,0" \
WL_DRS_OFF=1 WL_CAPTURE_SCENE=scenes/Example3D.wastescene \
WL_CAPTURE_SCALE=0.5 WL_CAPTURE_NEURAL=1 WL_CAPTURE_ACCUM=0 \
WL_FREEZE_TIME=1 WL_SCREENSHOT_LINGER=6 WL_NEURAL_STAGE=0 \
WL_SCREENSHOT=<off.png> WL_SCREENSHOT_FRAME=400 WL_CAPTURE_FLOAT=<off.bin>
```

then the same command with `WL_NEURAL_STAGE=3` for the stage-on pair.

**`WL_FREEZE_TIME=1` is not optional.** `u_Time` drives volumetric advection, cloud
noise and Gerstner waves from wall-clock, so two captures of "the same camera" are
different frames without it.

**Compare the `.bin`, never the `.png`.** The PNG is quantised to 8 bits and is floored
at the anchor's own quantisation, so a shader-vs-model comparison against it reads
`mean|d| 0.00144` where the true value is `0.000026`. The 8-bit difference is an artifact
of the container, not a defect in the stage.

## Reading the A/B

`neural_stage_ab.png` is 2332x1451 per side at half scale. The stage changes
**99.86%** of pixels, by a mean of **0.015160** and at most **0.034331** — which is to
say it changes essentially everything, and changes none of it much. That is the intended
shape: a residual enhancer that never replaces the frame. Geometry, shadows and edges
are preserved because they are in the anchor, which the stage only perturbs.

## Controls that make the numbers mean something

Two of these are the reason the comparison is trustworthy rather than merely green:

- **Zero-weight control.** With all 1140 weights zeroed the network is *exactly* the
  identity (`out = anchor`), and the stage reproduces the anchor to `mean|d| 0.000000`.
  This is what distinguishes "the stage reads the weights" from "the stage looks fine".
- **Reproducibility control.** Two identical stage-off captures compare bit-identical
  (`max|d| 0.00000000`). Reproducibility is not the problem; a contaminated capture is —
  a stale editor process produces a plausible-looking dump from the wrong run, and the
  symptom is indistinguishable from a broken shader.

Both controls are described in `docs/NEURAL_RENDERING.md` §7.
